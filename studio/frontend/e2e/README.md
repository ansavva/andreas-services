# End-to-end

Two modes, one set of specs.

```bash
npm run e2e            # stubbed. No AWS, no credentials, no stack. CI runs this.
npm run e2e:live       # the same specs against dev-up.sh and the seeded stack.
python e2e/fixtures/capture.py            # re-take the fixtures off the real API
python e2e/fixtures/capture.py --video    # just the MP4; needs no API and no token
```

## Why the fixtures are captured rather than written

They come from `http://localhost:8000` against the published dev-seed
character — the same 54-object fixture every developer's stack loads. A
hand-written stub drifts from the API silently and then asserts its own
imagination. `capture.py` is the only way they are produced, and it **scrubs
presigned URLs**: `/api/reel` answers with them, and a presigned URL carries the
signing key's access key id and a signature. The first capture put both straight
into git, and the browser then fetched real S3 for fourteen images — caught by
the spec that asserts nothing escapes to the network.

## The one fixture that is made rather than taken

`e2e-asset.mp4` — five seconds of one colour at 64x36, 1,741 bytes — is
generated by ffmpeg inside `capture.py` rather than captured, because **there is
nothing to capture it from**: the published dev seed is 54 stills, since runs,
scenes and movies are model output and cost money to make. Until it existed
`support/api.ts` answered every asset with the one-pixel PNG, so a `<video>` got
PNG bytes, fired `error`, and drew "this file could not be loaded" — which is
why no spec had ever opened `/o`. `playback.spec.ts` is what it unblocked.

It is in `capture.py` and not in a shell one-liner for the same reason the rest
of that file is: the tempting alternative is fetching a sample clip off the
internet, which is the move the header of `capture.py` exists to forbid. The
same run also strips the encoder's SEI banner, so what lands in git is frames
and nothing else.

`CLIP_ITEM` and `TEXT_NODE` in `support/api.ts` are the matching gap on the JSON
side — a clip and a `prompt.json` the seed does not hold either. Both are
**captured rows with a few fields overridden**, never objects typed out from
memory, so the shape stays the API's.

## Why there is no test flag in the app

`App.tsx` redirects to Cognito Managed Login unless `authenticated`, which is
whether `auth/oauth.ts` finds an ID token. `support/session.ts` seeds the token
store that module itself reads — one JSON blob under one localStorage key, the
same one the callback writes — so the app is signed in without a backdoor
compiled into the production bundle and without Cognito being contacted. The
app has to be *configured* for this: built with the Cognito variables empty it
renders "Auth is not configured" instead, which an early version of these specs
happily passed against.

## Live mode

`E2E_LIVE=1` points the same specs at `http://localhost:5173`, so it needs
`scripts/dev-up.sh` running and a real browser session. It is a local check
before a risky change, never CI: CI has no dev stack and never writes to AWS.
